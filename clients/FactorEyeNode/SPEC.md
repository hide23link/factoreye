# FactorEyeNode 仕様書

M5Stack（ATOM Lite など）の **ENV センサー（温度・湿度・気圧）と入出力ポートの値を、FactorEye に送る**スケッチ。
設定はすべて**スマホの設定画面**で行う（書き込み直さなくてよい）。使い方は [README.md](README.md)。

- 版: 0.3（WifiStarter 0.3.0 を同梱）
- 通信は [FactorEyeClient](../arduino-m5stack/)（`POST /api/ingest/readings`）。WiFi の設定と接続は、同梱の WifiStarter（`src/WifiStarter/`、第 7 章）が行う。このスケッチは「何を読んで、どこへ送るか」だけを持つ

---

## 1. 動作の概要

```
電源 ON
 ├─ ボタンを押している / WiFi が未設定 / 必須の設定が未入力 → 設定モード（赤点滅。設定画面を出す）
 │     スマホで M5-機種名-Setup-XXXX（例: M5-NanoC6-Setup-2449）に接続 → 設定画面で入力 → 保存して再起動
 └─ それ以外 → 通常モード
       1. 保存した WiFi に接続（青点滅 → 青点灯）
       2. ENV ユニットを初期化（見つからなければ黄色の点滅。30 秒ごとにやり直す）
       3. 送る間隔ごとに、センサーとポートを読んで FactorEye に送る
```

### LED

| 色 | 意味 |
|---|---|
| 赤の点滅 | 設定モード |
| 青の点滅 | WiFi に接続中（切れて再接続中も） |
| 青の点灯 | 動作中 |
| 黄色の点滅 | 異常（センサーが見つからない / 送信が長く成功していない） |

黄色の点滅になる条件（どれか）:
- 設定に問題がある: サーバーアドレスが `http://` で始まらない、または送るもの（センサー・入力ポート）が 1 つもない
- ENV ユニットが見つからない
- **書き込む ID のどれか 1 つでも**、最後に送れてから「間隔の 3 倍（ただし最短 2 分）」たっても送れていない（FactorEye に ID が未登録で 404 になっている場合も見つかる）

## 2. 保存した WiFi の引き継ぎ

- WiFi の SSID・パスワードは、本体のフラッシュ（NVS。名前空間 `wifistarter`、キー `ssid`・`password`）に保存される。プログラムを書き込み直しても、保存した設定は残る
- 書き込んで最初の起動では、必須の設定（サーバーアドレス・API キー）が未入力なので、**設定モード**に入る。設定画面の WiFi は「**保存済みの WiFi をそのまま使う**」が初期値になっているので、パスワードを入れ直さずに、センサーと送り先だけ入力して保存できる
- 保存後に再起動し、保存済みの WiFi で接続する

## 3. 設定画面の項目

| 見出し | 項目 | 保存名 | 内容 |
|---|---|---|---|
| ① WiFi | 保存済みの WiFi を使う / 変更する | （WifiStarter） | 変更するときは、近くの SSID から選んでパスワードを入れる（接続を確かめてから保存） |
| ② センサー | ENV ユニット | `sensor` | `auto`（既定。ENV2・ENV3・ENV4 を**自動で見分ける**）/ `none`（つながない。ポートだけ使う）。以前の版で保存した `ENV2`・`ENV3`・`ENV4` は、`auto` として扱う（設定を変えずに、ユニットを差し替えられる） |
| ③ 送り先 | サーバーアドレス | `server` | FactorEye のアドレス（例 `http://192.168.1.50:8000`）。**必須**。`http://` で始める（FactorEyeClient が https 未対応。https は 9 章）。前後の空白と末尾の `/` は取って保存・使用する |
| | API キー | `apikey` | **なしでも動く**（空なら `X-API-Key` ヘッダーを付けずに送る）。キーが必要なサーバー（FactorEye の self-hosted の `INGEST_API_KEY`）のときだけ入力する。画面には値を出さない。空のまま保存すると今の値を残し、「保存してある値を消す」にチェックすると消える |
| | 送る間隔 | `interval` | 10 秒 / 30 秒（既定）/ 1 分 / 5 分 |
| ④ 書き込む ID | 温度・湿度・気圧 | `id_temp`・`id_humi`・`id_press` | FactorEye のセンサーの ingestKey。既定は `atom-<識別>-temp`・`-humi`・`-press`（頭は機種で変わる: `atom`・`atoms3`・`nanoc6`。`<識別>` は、この本体のアクセスポイントの MAC の下 4 桁。設定モードの SSID の末尾と同じ。台ごとに違う初期値にして、複数台が同じ ID に書いて値が混ざるのを防ぐ）。半角の英数字と `.` `_` `-` だけ。センサーが `none` のときは出ない |
| ⑤ 入出力ポート | ポートごとの使い方 | `g19_mode` など | 下の表 |
| | ポートごとの書き込む ID | `g19_id` など | 入力にしたポートだけ表示・必須。既定は `atom-<識別>-G19` のように付ける |

FactorEye には、**同じ ID のセンサーを先に登録しておく**（未登録の ID は 404 で送れない）。単位は温度 ℃・湿度 %・気圧 hPa。
複数台で使うときは、台ごとに ID を変える（同じ ID に書くと、値が混ざる）。

### ポートの使い方

| 使い方 | 動き | 送る値 |
|---|---|---|
| 使わない | 何もしない | |
| **パルスを数える（生産数）** | 割り込みで、ON の信号を数える（下の「生産数」） | 5 秒ごとの個数（0 を含む）と、稼働・停止（1/0。任意） |
| デジタル入力 | `INPUT` | 0 / 1 |
| デジタル入力（プルアップ） | `INPUT_PULLUP`（乾接点のスイッチ向け。閉じると 0） | 0 / 1 |
| アナログ入力（電圧） | `analogReadMilliVolts` | V（ボルト） |
| デジタル出力 | 出力にして 0（LOW）にする。**使い方は今後追加**（今は 0 のまま） | |

選べる使い方は、ポートごとに変わる: アナログ入力は ADC1 のポートだけ、プルアップと出力は入力専用のポートでないものだけ。

## 3.1 生産数（パルスを数える）

赤外線・近接センサーなどが、物体が通ったときに出す ON 信号（デジタル）を数えて、**5 秒ごとの個数**を FactorEye に送る。FactorEye の生産数のウィジェットは、値の**合計**（`SUM`）で「直近 1 時間」「本日」を出すので、累積ではなく、**窓ごとの増分（0 を含む）**を送る。

- **取りこぼさない**: 数えるのは割り込み（`PulseCounter.h`）。`loop()` が通信で数秒止まっても、数え続ける。1 秒未満の連続（0.3 秒間隔など）も数える。
- **デバウンス**: 1 つ数えてから、設定の時間（ミリ秒）の間に来た信号は、数えない（チャタリングを 1 つにする）。物体の最短の間隔より、短くする。
- **5 秒の窓**: 個数は、ENV の送る間隔（10 秒〜5 分）とは別に、**固定 5 秒**で送る。WiFi が切れている間は、個数を取り出さず、カウンタに残す（つながったあと、合計で送る）。サーバーに届かない状態が長く、未送信が 60 件以上溜まったときも、取り出さない（FactorEyeClient の溜め場 100 件から、個数が押し出されないように）。
- **稼働・停止（時間で判定）**: 最後のパルスから、「**停止とみなす秒数**」以内なら稼働（1）、超えたら停止（0）。ちょうどの秒数は稼働。**起動直後は、起動を最後のパルスとみなす**（再起動の直後に、偽の「停止」を出さない）。10 秒以上の間隔で動くラインは、この秒数を、その間隔より長くする。
- **別の信号を足せる作り**: 稼働・停止の判定は `RunJudge.h` の `isRunning(時間による判定, 外部の信号)` に集まっている。外部の信号（`ExternalRun`: 不明・稼働・停止）が「稼働」か「停止」なら、そちらを優先し、「不明」なら、時間による判定を使う。**いまは外部の信号を入れる場所がなく、常に「不明」**。人が入力する稼働・停止（スマホ画面、別の ATOM のボタン）や、別の入力ポートの信号は、別の実装で足す。
- **FactorEye 側**: 変更は要らない。生産数ウィジェットの稼働表示は「最新の 1 件が 0 より大きいか」だけなので、間隔の長いラインでは、動いていても「停止中」と出る。正しい稼働・停止は、**稼働 ID** のセンサー（1/0）で見る（下限のしきい値で、停止の通知もできる）。

設定（ポートごと。「使い方」を「パルスを数える」にしたときだけ表示）:

| 項目 | 保存名（G19 の例） | 内容 |
|---|---|---|
| センサーが ON のときの電圧 | `g19_lvl` | `low`（既定。NPN・接点。内部プルアップを使う。立ち下がりで数える）/ `high`（PNP。立ち上がりで数える）。入力専用のポート（G34〜G39）は、内部プルアップがないので、`low` のときは外付けの抵抗が要る |
| デバウンス（ミリ秒） | `g19_deb` | 数字。既定 20、0〜1000 |
| 停止とみなす秒数 | `g19_stop` | 数字。既定 60、1〜86400 |
| 書き込む ID（個数） | `g19_id` | 必須。個数を送る |
| 稼働 ID | `g19_idrun` | 任意。空なら送らない。5 秒ごとに 1（稼働）/ 0（停止）を送る |

**レート制限（100 回/分/IP）**: 1 つのポートで、個数と稼働で、5 秒ごとに 2 回 = 24 回/分。ENV（30 秒間隔）が 6 回/分。**パルスのポートは 3 つまで**を目安にする（約 78 回/分）。それ以上は、稼働 ID を使わない、または間隔・台数を見直す。
**データ量**: 0 個の窓も送るので、1 つの ID で 1 日 17,280 行（1 年で約 630 万行）。FactorEye の self-hosted は、古いデータを自動で削除しない（再検討の目安は 1,000 万行）。

## 4. 機種ごとの違い（`Boards.h`）

機種はビルドのボード設定で決まる（`Boards.h` が選ぶ）。新しい機種に対応するときは、`Boards.h` に機種を 1 つ足すだけでよい。
設定モードのアクセスポイント名は「**M5-機種名-Setup-XXXX**」（`XXXX` は本体ごとの MAC の下 4 桁）: ATOM Lite は `M5-ATOMLite-Setup-XXXX`、ATOMS3 Lite は `M5-ATOMS3Lite-Setup-XXXX`、NanoC6 は `M5-NanoC6-Setup-XXXX`。どの機種かが、スマホの WiFi 一覧で分かるようにするため。

| 機種 | ボタン | LED | Grove（SDA / SCL） | 使えるポート |
|---|---|---|---|---|
| ATOM Lite（ボード: M5Atom） | G39 | G27 | G26 / G32 | G19・G21・G22・G23・G25（デジタルのみ。WiFi 中はアナログ不可）、G33（アナログ可）、G39（本体ボタン。入力のみ） |
| ATOMS3 Lite（ボード: M5AtomS3） | G41 | G35 | G2 / G1 | G5・G6・G7・G8（ESP32-S3 の G1〜G10 は ADC1 なので、すべてアナログ可）。**ピンは M5 のサンプルから取った値で、実機未確認** |
| M5Stack Basic（ボード: M5Core） | A（G39） | **なし**（画面に状態を出す） | G21 / G22（Grove の Port A） | G26・G36（Port B）、G35（M-Bus）。Port C（G16・G17）は、PSRAM つきの個体が使うので含めない。ボタン A を、**起動後 3 秒の間**に押すと設定モードに入る。画面（320×240）に、設定モードの手順（つなぐ WiFi 名と設定画面のアドレス）と、動作中の状態・温度・湿度・気圧を、**英数字の大きな文字**で出す（`StatusScreen.cpp`。最低限の表示で、日本語フォントは入れない） |
| NanoC6（ボード: M5NanoC6、ESP32-C6） | G9 | G20（電源 G19） | G2 / G1 | **なし**（外に出ているピンは Grove の 2 本だけで、ENV ユニットが使う）。ボタン G9 は起動のモード選びのピンなので、**電源を入れてから 4 秒の間にボタンを押す**と設定モードに入る（その間、LED が白く点滅）。ボタンを押したまま電源を入れると、ダウンロードモードになるので注意 |

- ESP32 は WiFi を使っている間、ADC2 のピン（G0・G2・G4・G12〜G15・G25〜G27）をアナログ入力に使えない
- ATOM Lite の G39 は本体ボタン。起動時に押すと設定モードに入る（通常は入力としても読める）

## 5. ENV ユニット

| ユニット | 温湿度 | 気圧 | I2C アドレス |
|---|---|---|---|
| ENV2 | SHT30 | BMP280 | 0x44 / 0x76 |
| ENV3 | SHT30 | QMP6988 | 0x44 / 0x70 |
| ENV4 | SHT40 | BMP280 | 0x44 / 0x76 |

- ライブラリは **M5Unit-ENV**（`M5UnitENV.h`）。気圧は Pa で返るので、100 で割って hPa にして送る
- ありえる範囲の外の値は送らない（つながっていない・故障のサイン）: 温度 -40〜125 ℃、湿度 0〜100 %、気圧 300〜1100 hPa
- ユニットが見つからないときは、シリアルに表示し、黄色の点滅で知らせる。30 秒ごとに初期化をやり直すので、あとから挿しても動く

### 自動判別（`EnvSensor.cpp`）
起動時に、Grove の I2C で応答するアドレスを調べて、ユニットを見分ける（結果はシリアルに `[EnvSensor] 自動判別: ENV3` と出る）。

| 応答 | 判定 |
|---|---|
| SHT(0x44) と QMP6988(0x70) | ENV3 |
| SHT(0x44) と BMP280(0x76) | ENV2 か ENV4（下のとおり、温湿度センサーで見分ける） |
| SHT(0x44) がない、または気圧センサーがない | 見つからない（黄色の点滅。30 秒ごとにやり直す） |

ENV2（SHT30）と ENV4（SHT40）は、温湿度センサーが同じアドレス 0x44 なので、**シリアル番号の読み出し**で見分ける: SHT40 は 1 バイトのコマンド `0x89`、SHT30 は 2 バイトのコマンド `0x3780` で、6 バイトの応答（2 バイト + CRC を 2 組）を返す。CRC（多項式 0x31、初期値 0xFF）が合う方を採用する（3 回まで試す）。どちらも確かめられなかったときは、ENV4 とみなす。
**実機で確認済み: ENV3・ENV4（自動判別とも）**。ENV2 は未確認。

## 6. FactorEye への送信

- ライブラリは **FactorEyeClient**（`factoreye/clients/arduino-m5stack`）。1 つの値ごとに `send(ID, 値)` を呼ぶ
- 送れなかった分は、ライブラリが溜めて（最大 100 件）、次回まとめて再送する。失敗が続くと待ち時間を延ばす（最大 30 秒）
- WiFi が切れている間は、読み取りも送信もしない（つなぎ直しは WifiStarter が行う）
- **レート制限**: FactorEye は IP ごとに 100 回/分。1 回の周期で送る回数は「温度・湿度・気圧の 3 ＋ 入力ポートの数」で、それぞれ 1 回の通信になる。目安: **台数 × 1 周期の送信数 × 60 ÷ 間隔（秒）≦ 100**。例: ポート 3 つを入力にして間隔 10 秒なら、1 台で 1 分に 6 周期 × 6 回 = 36 回（3 台で上限）。既定の 30 秒間隔なら、最大 10 回 × 2 周期 = 20 回/分なので、5 台で上限に達する。超えると 429 が返り、クライアントが待って再送する（値は遅れて届く）。同じ IP（同じルーター・同じトンネル）から多くの台をつなぐときは、間隔を延ばす
- 受信時刻は FactorEye のサーバーが付ける（端末の時刻は送らない）

### WifiStarter（`src/WifiStarter/`）

WiFi の設定・保存・接続だけを受け持つ部品。スケッチの中に同梱していて、別にインストールする必要はない。

- **設定モード**: ボタンを押したまま起動する／WiFi が未設定／必須の設定が未入力、のどれかで入る。本体がアクセスポイント（SSID は `M5-機種名-Setup-XXXX`、パスワードなし、IP は `192.168.100.1`）になり、スマホで接続すると設定画面が自動で開く（開かないときは `http://192.168.100.1/` を開く）。LED は赤の点滅
- **WiFi は、実際に接続できたことを確かめてから保存する**ので、間違ったパスワードが保存されることはない。このスケッチの項目（センサー・送り先・ID・ポート）は、WiFi の接続に成功してから保存される（「保存済みの WiFi をそのまま使う」ときは、そのまま保存）
- **通常モード**: 保存した WiFi に接続する（青の点滅 → 青の点灯）。運用中に切れたときは、自動でつなぎ直す
- **設定画面の項目**: `.ino` の `registerSettings()` が登録する（`addText`・`addSelect`・`addNumber`・`addPassword`。必須・形式・表示の条件の指定つき）。`required()` の項目が未入力だと、設定モードに入る
- **LED で異常を知らせる**: アプリが `setWarning(true)` を呼ぶと、黄色の点滅

## 8. 開発環境

- Arduino IDE 2、ESP32 ボード定義 3.0 以上（確認したのは 3.3.12）。ボード: ATOM Lite は `M5Atom`、ATOMS3 Lite は `M5AtomS3`
- ライブラリ: **FactorEyeClient**（このリポジトリの `clients/arduino-m5stack`）、**M5Unit-ENV**（機種によっては **M5Unified**）。WifiStarter は同梱
- コマンドで確認する（リポジトリの `clients/` で実行）:
  ```sh
  arduino-cli compile --fqbn esp32:esp32:m5stack_atom --library arduino-m5stack FactorEyeNode
  ```
- **M5Stack Basic は、パーティションを「No OTA (2MB APP/2MB SPIFFS)」にする**（標準の 1.2MB では、画面の部品 M5Unified の分が入らない）。コマンドでは `--fqbn esp32:esp32:m5stack_core:PartitionScheme=no_ota`
- コンパイルを確認した機種と使用量: ATOM Lite（フラッシュ 37%）、ATOMS3（86%。余裕は小さい）、NanoC6（標準のパーティションで 96%。余裕を持たせるなら `PartitionScheme=no_ota` で 60%）。気圧・ENV のライブラリが大きいため
- **WiFi を引き継ぐ書き込み方**は、Arduino IDE の通常のアップロード。「Erase All Flash」や merged.bin の書き込みでは、保存した WiFi が消える

| テスト | 確かめること |
