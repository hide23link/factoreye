# テスト工場エミュレータ

センサーや実機が無くても、FactorEyeのダッシュボード・アラーム機能をそれらしいデータで
試せるようにするための開発・デモ用ツールです。機械1台分の「生産数・温度・電力」を
5秒ごとにシミュレートしてbackendへ送信します。本体や`clients/`配下の公式クライアントとは
別物（これはテスト用の偽の機械）で、backendとは別プロセスとして動かします。

## 使い方

```bash
# backendが起動していること（リポジトリ直下で）
docker compose up -d

# 別ターミナルで
cd tools/factory-emulator
python3 emulator.py
```

初回起動時にセンサー（生産数・温度・電力）を自動登録します（既に登録済みならスキップ）。
以降はFactorEyeのダッシュボードにグラフウィジェットを追加すれば、変動するデータが
リアルタイムで表示されます。終了は Ctrl+C。

self-hosted の `INGEST_API_KEY` を既定値から変えている場合は、同じ値を環境変数 `INGEST_API_KEY` で渡します。
既存のセンサーと名前・取り込みキーを重ねたくないときは、`EMULATOR_SUFFIX`（例: `EMULATOR_SUFFIX=-2`）で識別子をずらせます。

依存ライブラリはありません（`clients/raspberry-pi/factoreye_client.py` を再利用、標準
ライブラリのみ）。

## シミュレーションの挙動

- **生産数**（個、実カウント値）: 直近5秒間で実際に生産した個数。内部の生産負荷指標
  （0〜100、ゆるやかにランダムウォーク）から導いており、通常運転中は負荷に応じて
  1tickあたり数個程度のばらつきが出る。FactorEyeダッシュボード側で「直近1時間」
  「本日累計」のように合計して使う前提の値（個/分のような瞬間レートではない）
- **温度・電力**: 内部の生産負荷指標に連動（高負荷ほど高温・高消費電力）。実機の熱慣性に
  近づけるため、値は指数平滑でゆっくり目標値へ近づく（カクカク飛ばない）
- **一時停止**: 一定確率で発生し、生産数は即座に0個、電力は待機電力、温度は徐々に室温へ。
  15〜90秒程度でランダムに終わり、通常運転へ復帰する

### 本日の生産目標を試したい場合

ダッシュボードで生産数センサーを「稼働ステータス」ウィジェットに割り当て、編集画面
（⚙）から「本日の生産目標数」を入力すると、本日累計に対する達成率が表示されます。

## アラーム機能を試したい場合

自動登録されるセンサーには閾値（上限・下限）を設定していません。FactorEyeの
「設定」→「センサー」から、例えば温度センサーに上限40°C程度を設定すると、高負荷が
続いたタイミングでアラームが発生する様子を確認できます。

自動のランダムウォークは狙った値に調整しづらい（いつ閾値を超えるか待たないと
分からない）ため、確実にアラームを発生/解除させたい時は下記の手動操作画面を使う方が早い。

## 手動操作画面（しきい値アラームを狙って出したい時）

`emulator.py` 起動時に自動で一緒に立ち上がる、スライダーで値を直接操作できる簡易Web画面。

```
http://localhost:8765
```

- 生産負荷・温度・電力をそれぞれ独立に「自動」⇄「手動」切り替え可能
- 「手動」ONにした指標は、自動のランダムウォーク/一時停止ロジックを無視し、スライダーの
  値へ少しずつ収束する。収束した後も小さなランダム変動が乗り続ける（ピタッと静止はしない）
- スライダーをしきい値の外側まで動かせば、その場でアラームを発生させられる。しきい値の
  内側に戻せば解除される
- 「手動」をOFFに戻すと、その指標は通常のシミュレーションに復帰する
- 追加ライブラリ不要（標準ライブラリの`http.server`のみ、`control_server.py`）

生産負荷スライダーは「生産数」センサーの計算元（0〜100%）であり、生産数そのもの
（個/5秒、最大5個）を直接指定するものではない点に注意。温度・電力は個別にスライダーで
直接値を指定できる。

## SaaS 版（本番）へ送る

環境変数で送信先とログインを指定します。トークンはファイルに書かず、パスワードは画面に出さずに聞きます。

```bash
cd tools/factory-emulator
FACTOREYE_EMAIL=<メール> FACTOREYE_HOST=https://factoreye.hide23.link \
  EMULATOR_SUFFIX=-demo EMULATOR_RUN_SECONDS=300 python3 emulator.py
```

- `FACTOREYE_EMAIL` を指定すると、起動時にパスワードを聞いてログインします（トークンはメモリ上だけ）。`FACTOREYE_TOKEN` を直接渡すこともできます。
- 起動時に、送信先のセンサーが自分のワークスペースにあるかを確かめてから送ります（取り込みキーは全体で一意のため）。
- `EMULATOR_RUN_SECONDS`（秒）で、指定時間だけ送って終了します。未指定なら止めるまで送り続けます。
- `EMULATOR_SUFFIX` で、センサーの名前と取り込みキーを区別できます（既存のセンサーと衝突させないため）。
- Python の既定の User-Agent は、本番の前段で拒否されるため、エミュレータは名前を付けて送ります。
- macOS の python.org 版 Python で証明書のエラーが出るときは、`SSL_CERT_FILE=/etc/ssl/cert.pem` を付けるか、「Install Certificates.command」を実行してください。

## 設定変更

`emulator.py` 冒頭の定数を直接書き換えてください（`SEND_INTERVAL_SECONDS` / 一時停止の発生確率・長さ等）。
送信先と認証は、上の環境変数で指定します。
