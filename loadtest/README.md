# 負荷テストの道具

FactorEye に負荷をかけて、応答時間・エラー・データの欠けを確かめる道具です。**本番には向けないでください。**

| フォルダ | 内容 |
|---|---|
| `emulator/` | 多数の利用者が同時にセンサー値を送り、画面を閲覧・設定変更する状況を再現する（Web 画面で想定を変えられる） |
| `device_sim/` | OSS 版の機器（機器ごとのキー・`samples` 形式・1 秒ごとの測定）の送信を、1 プロセス 1 か所で再現する |
| `tests/` | 両方の単体テスト（外部サービス不要） |

## emulator

```bash
cd loadtest
pip install -r requirements.txt
python -m emulator            # http://127.0.0.1:8100 で画面を開く
pytest                        # 単体テスト
```

画面の「想定」（同時ユーザー数 1〜100・1 人あたりのセンサー数・送信間隔・閲覧の並行数・値の傾向など）を変えて「想定を反映」すると、実行中でもすぐ反映されます。「開始」「停止」「計測をリセット」で実行を制御し、API ごとの件数・エラー数・p50/p95/p99・リクエスト/秒を表示します。

- **本番かもしれないホストへの実行は拒否します**（`localhost`・私設アドレス・ドットのない名前・`.local` などだけを通す。`emulator/scenario.py` の `is_production_target`）
- 既定では `127.0.0.1` にだけ待ち受けます（外に出すと、誰でも負荷をかけられるため）
- OSS 版に向けるときは、想定に `oss_mode`（true）と `ingest_api_key`（対象の `INGEST_API_KEY`）を指定します（登録・ログインを省き、`X-API-Key` で送る）
- 取り込みは IP ごとに 100 回/分の制限があります。1 台から多数のセンサーを送ると 429 になるので、対象の `.env` で `INGEST_RATE_LIMIT=off` などに緩めます
- **既知の制限**: SaaS 版に向ける流れは、廃止した `/api/auth/register`・`/login` を使っているため、パスキー導入後はそのままでは動きません（[`docs/architecture.md`](../docs/architecture.md) §13）

## device_sim

1 プロセス（コンテナ）＝ 1 か所 ＝ 3 要素（電圧・電流・電位）。1 秒ごとに測り、「時刻＋3 要素」を機器ごとのキー（`X-Device-Key`）で送ります。送信に失敗した分は溜めて、次の送信でまとめて再送します（時刻つきなので二重になりません）。送り方は `MODE=second`（毎秒 1 回）か `batch`（既定。`BATCH_SECONDS` 個ためて 1 回）です。

前提は、取り込み側が `INGEST_DEVICE_TIME=on`（同じ IP から多数を送るなら `INGEST_RATE_LIMIT=off` も）であることです。準備から後片付けまでは `device_sim/scripts/` のスクリプトで行います。

| スクリプト | 内容 |
|---|---|
| `setup_devices.sh <か所の数> <キーの置き場>` | 取り込み側にセンサーと機器を作り、キーを保存する（`TARGET` に取り込み側の ssh の宛先） |
| `run.sh <か所の数> <batch｜second> <秒数> <取り込みの URL>` | か所の数だけコンテナを起動して送る |
| `monitor.sh` | 取り込み側の負荷と件数を記録する（任意） |
| `check.sql` | か所ごとに、件数・時間の幅・重ならない時刻の数が一致するか（欠け・重複がないか）を確かめる |
| `stop.sh`・`cleanup.sql` | 止める・試験用のセンサーと機器を消す |
