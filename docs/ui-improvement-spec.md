# 画面改善 7 点の仕様（2026-11-20）

Grafana・Ambient と見比べて決めた改善。承認済みの「操作室風」の見た目（暗い背景・色の意味は 6 つだけ・数字は等幅・線と数値は同じデータから計算）に合わせる。
モック: https://claude.ai/artifact/A6gCGsjwvtMPyQCaQd9TeR （番号は下の番号と同じ）

## 共通のルール

- 色の意味: 白=今の値 / 水色=しきい値 / 桃=目標・予測 / 橙=注意 / 赤=警報 / 灰=停止・前日。新しい色を増やさない。
- 線・帯・表・凡例は、すべて同じ取得データから計算する（目分量で描かない）。
- スマホ幅（約 400px）でも崩さない。キーボードで操作でき、ボタンには `aria-label` を付ける。
- 新しい表示設定は、この端末の `localStorage`（読み書きは try/catch）。サーバーの DB は変えない（7 を除き、バックエンドの変更なし）。
- 各ファイルの先頭に「何をする部品か・誰が使うか・引数」の説明を書く（`guidelines/03-development-standards.md` の「理解しやすさ」）。
- 試験: 計算は `lib/` の関数に切り出して vitest で試す。部品は testing-library。`npm run typecheck`・`lint`・`test` がすべて通ること。
- 確認: ローカルの Docker（バックエンド 8010 番）と vite（3001 番）、`tools/pi-sync/pi-sync.sh --follow` で取り込んだラズパイの実データ。

## 1. 警報の帯

- 対象: 計器グラフ（TrendStack）の各行、センサーグラフ（SensorGraph）。複数センサー比較は対象外。
- 区間の決め方: しきい値（上限の注意・警報、下限の注意・警報）を超えている区間を、連続した 1 つの帯にする（`lib/threshold-bands.ts` に `computeBands(points, thresholds)`。戻り値は `{ startMs, endMs, level, extreme }[]`）。`level` は区間内の最悪、`extreme` は区間内の最高（下限側は最低）の値。
- **警報の記録（alarms 表）は使わない。** ラズパイの alarms は 0 件で、グラフの線の色と帯が食い違うのを避けるため。
- 描き方: 縦の帯を、塗り（橙 / 赤、透明度 0.16）と上辺の 3px の線で描く。幅は最低 2px。帯の判定は区間の最高・最低で行い、線の色は線の値で決める（両者は一致しない場合がある）。
- 操作: カーソルが帯の中にあるとき、値の一覧に「警報 11:42〜12:58 最高 89.2」を出す。グラフの見出しに「警報の帯」の切り替え（既定は入）。
- 受け入れ: しきい値が未設定なら帯なし。7D でも描ける。間引きで 1 点だけ超えた場合も帯が出る。

## 2. ⋮ メニュー

- 場所: ウィジェットの見出しの右（既存の歯車・複製・削除は変えない）。対象は、センサーグラフ・計器グラフ・複数センサー比較・ゲージ以外のグラフ系。
- 項目:
  - 全画面で見る（`V`）: その 1 枚を画面いっぱいに出す。Esc で戻る。
  - データを表で見る（`T`）: グラフの下に表を開く（新しい順、先頭 12 行、「もっと見る」で追加）。
  - CSV を保存: 表示中の範囲の値。列は `時刻(JST,ISO 8601)`・センサーごとの値。1 行目に名前と単位。UTF-8（BOM 付き、Excel 用）。ファイル名は「センサー名_期間.csv」。**取得済みのデータから作る（新しい API は作らない）。**
  - この期間のリンクをコピー: 既存の `lib/graph-link.ts` を使う。
- 見送り: 「画像として保存」（描画が SVG と混在しているため、第 2 段階）。
- 受け入れ: CSV の行数がグラフの点の数と一致。日本語の名前が文字化けしない。メニューは Esc・外側のクリックで閉じ、矢印キーで選べる。

## 3. 更新間隔

- 場所: 画面上部の時間の操作（`TimeRangeControls`）に「更新 ▾」と手動の更新ボタンを足す。**「一時停止」は既にある。**
- 選択肢: 各グラフの設定に従う（既定。今の動き）/ Off / 10 秒 / 30 秒 / 1 分 / 5 分。選んだら、全グラフの取り直しの間隔をこれで上書きする。Off のときは「⟳」で手動更新（キャッシュを無効にして取り直す）。
- 状態: `store/useRefreshStore.ts`（端末に保存）。`LIVE_CHART_INTERVAL_MS` と、グラフごとの `refreshSeconds` に優先する。
- 表示: 「更新 07:51:41」の最終更新時刻を出す。Off のときは橙で「手動」。
- 受け入れ: 切り替えると、次の取り直しから反映。キオスク（画面表示モード）でも同じ値で動く。

## 4. 昨日の重ね

- 対象: 計器グラフの各行とセンサーグラフ（1 センサーだけのとき）。複数センサー比較は対象外。
- 操作: 見出しに「比較: なし / 昨日 / 先週」（既定は なし。端末に保存）。
- 描き方: 同じ間引き API を、範囲を 24 時間（先週は 7 日）前にずらして取り、今日の時刻の位置に灰色の点線で重ねる。縦軸の範囲は、今日と比較の両方が入るようにそろえる。
- カーソルの値の一覧に「昨日 62.4（差 +4.1）」を出す。
- 無効になるとき: 保持期間（SaaS は 14 日）の外になる範囲は、ボタンを押せなくして理由を出す。
- 受け入れ: 比較側の取得が失敗しても、今日の線は消えない。固定の表示（過去の期間）でも、その期間の 1 日前が重なる。

## 5. 凡例の表

- 対象: 複数センサー比較（MultiSensorComparison）。グラフの下に表。
- 列: 名前（線の色の見本つき）/ 値（カーソルがあればその時刻、なければ最新）/ 最小 / 最大 / 平均（スマホは平均を隠す）。
- 操作: 行のクリックで、その 1 本だけ表示（他は薄く）。もう一度クリックで戻る。Shift・Ctrl・Cmd クリックで複数。キーボード（Enter・Space）でも操作でき、`aria-pressed` を付ける。状態は保存しない。
- 受け入れ: 数値は線と同じデータから。色は設定した色と一致。

## 6. 状態の帯（新しいウィジェット `StateTimeline`）

- センサーを複数選び、1 センサー 1 行の色の帯を、時間をそろえて並べる。
- 状態: 稼働（緑系の落ち着いた色）/ 警報（赤・橙。しきい値の超過）/ 停止（灰。「停止とみなす値」以下。設定した行だけ）/ 受信なし（橙の斜線）。優先は 受信なし > 警報 > 停止 > 稼働。
- 計算: 間引き API の区間（約 144 本）から、`lib/state-timeline.ts` で決める。区間に値が無ければ受信なし。
- 表示: 帯にカーソルを置くと「警報 11:42〜12:58（76 分）」。行の右に稼働率（%）。凡例の色の見本。
- 追加の作業: `types.ts` の `WidgetType`、ウィジェットの追加パレット、`WidgetCard` の切り替え、設定画面（センサー選択・停止とみなす値）。バックエンドの変更が要るかは、ウィジェットの種類の検証を確認して決める。
- 受け入れ: 24 時間・7D で描ける。センサーが 30 本でも重くならない（表示している分だけ取る）。

## 7. 届いたらすぐ表示

- 条件: センサー一覧に、この端末が前に見たことのないセンサーが現れたとき（初回は、既存のセンサーをすべて「見た」ことにして通知しない。端末に保存）。
- 表示: 画面の上にカードを出す。「新しい機器『ENV-07』から最初のデータが届きました」、直近 5 時間のミニグラフ、「ダッシュボードに追加」「あとで」。
- 「ダッシュボードに追加」: 開いているダッシュボードに、そのセンサーのセンサーグラフを 1 枚足す（なければ新しいダッシュボードを作る）。
- バックエンドの変更なし（センサー一覧の取り直しで検知）。
- 受け入れ: 同じセンサーを 2 回通知しない。複数同時に届いたら 1 枚にまとめる。

## 決めること

1. 6 の「稼働」の定義。案: 値を受信していて、警報でなければ稼働。「停止とみなす値」は任意で設定した行だけ。
2. 3 の 10 秒を SaaS でも許すか。案: 10 秒は OSS（自前ホスト）だけ。SaaS は 30 秒以上。
